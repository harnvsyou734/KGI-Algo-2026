# มีอะไรเปลี่ยนในแต่ละเวอร์ชัน

เวอร์ชันของ `tradeSim` ดูได้จากชื่อไฟล์ zip ที่โหลด (`tradeSim<version>.zip`) โหลดตัวใหม่แล้วแตกทับในโฟลเดอร์ repo ของทีม
แบบเดียวกับครั้งแรก

## 0.2.6

### การจับคู่ limit order (มีผลกับผลลัพธ์)
- **order ที่ค้างในบุ๊คจะได้หุ้นเมื่อตลาดซื้อขายที่ราคา "เลย" ราคาที่ตั้งไว้เท่านั้น** คือ**ต่ำกว่า**ราคาที่ตั้งซื้อ
  หรือ**สูงกว่า**ราคาที่ตั้งขาย และได้ที่ราคาที่ตั้งไว้
  - ตั้งซื้อที่ 2.94: ตลาดซื้อขายที่ 2.94 → ยังไม่ได้ (ไม่ว่าจะซื้อขายกันที่ราคานั้นมากแค่ไหน) · ตลาดซื้อขายที่ 2.92 → ได้ที่ 2.94
  - ตั้งขายที่ 2.96: ได้เมื่อตลาดซื้อขายที่ 2.98 ขึ้นไป (ได้ที่ 2.96)

  **ทำไมราคาแค่แตะแล้วยังไม่ได้?**
  ในเวอร์ชัน 0.2.5 order ที่ค้างอยู่ได้หุ้นครบทันทีที่มีการซื้อขายที่ราคานั้น เช่น มีคนขาย TTB แค่ 100 หุ้นที่ 2.94
  แต่ order ซื้อ 68,000 หุ้นที่ตั้งรอไว้ได้ครบทั้งหมด เหมือน order ของเราอยู่หัวคิวเสมอ และได้หุ้นมากกว่าที่ตลาดซื้อขายกันจริง
  กลยุทธ์ที่ตั้งซื้อที่ราคาเสนอซื้อและตั้งขายที่ราคาเสนอขายวนไปเรื่อยๆ จึงได้กำไรแทบทุกรอบใน simulator ซึ่งตลาดจริงทำไม่ได้

  ในตลาดจริง คนที่ตั้งราคาเดียวกันไว้ก่อนจะต่อคิวอยู่ข้างหน้า order ที่เพิ่งวางจะอยู่**ท้ายคิว** การซื้อขายที่ 2.94
  อาจเป็นของคนที่อยู่ข้างหน้าทั้งหมด ข้อมูล tick บอกแค่ว่ามีการซื้อขาย ไม่บอกว่าคิวที่ราคานั้นยาวแค่ไหน
  ระบบจึงถือว่า order ของเราอยู่ท้ายคิวเสมอ ถ้าตลาดลงไปซื้อขายที่ 2.92 ได้ แปลว่าคิวที่ 2.94 หมดแล้ว รวมถึงของเราด้วย
  จึงนับว่าได้หุ้นแน่นอน

  ผลที่ตามมา: limit order ใน simulator จะได้หุ้นยากกว่าตลาดจริงเล็กน้อย (ในตลาดจริง ถ้าคิวสั้น อาจได้หุ้นโดยราคาไม่ต้องเลยไป)
  แต่จะไม่ได้หุ้นง่ายเกินจริงแบบเวอร์ชันเดิม
- **ได้ไม่เกินปริมาณของ tick ที่ทำให้ได้ของ** (ปัดลงเป็นหลัก 100 · tick ที่ต่ำกว่า 100 หุ้นไม่ทำให้ได้ของ)
  ส่วนที่เหลือค้างในบุ๊คต่อ ถ้า order ของทีมหลายตัวได้ของจาก tick เดียวกัน จะแบ่งปริมาณกันตามลำดับที่วาง
- **order ที่ได้ของทันทีตอนวาง** (ราคาเสนอขายอยู่ที่หรือต่ำกว่าราคาซื้อของเรา) ยังได้ทันทีเหมือนเดิม แต่ได้ไม่เกินปริมาณของ tick
- **เพดานปริมาณของวัน** คิดตามหุ้นที่สั่ง (เดิมใช้ของหุ้นที่ `on_data` กำลังประมวลผล) และหักปริมาณที่ทีมซื้อขายหุ้นนั้นไปแล้วในวันนั้น
- market order ไม่เปลี่ยน

**ควรทำ:** ทีมที่ใช้ `create_order_to_limit` ควรรันทดสอบกลยุทธ์ใหม่ เพราะผลจะต่างจาก 0.2.5
กลยุทธ์ที่คิดว่าได้หุ้นครบตามจำนวนทันทีหลังวาง limit ให้เช็กจาก `get_all_stocks_info()` หรือ `get_open_orders()` แทน

### transaction log และ Round-Trip
- order ที่ได้ของหลายครั้ง จะมีหลายแถวใน transaction log ที่ `Order Number` เดียวกัน (แถวละครั้งที่ได้ของ)
- `get_open_orders()` แสดง `Volume` เป็นจำนวนที่**ยังค้าง** ไม่ใช่จำนวนที่สั่งตอนแรก
- order ที่ได้ของไม่ครบภายในวัน: ส่วนที่ได้แล้วอยู่ในพอร์ต ส่วนที่เหลือถูกยกเลิกตอนปิดตลาดเหมือน order ค้างทั่วไป
  และ**ไม่มีแถวใน log** ถ้ายังต้องการ ให้วางใหม่วันถัดไป และเช็คจำนวนที่ถือจริงด้วย `get_all_stocks_info()`
- ทุกครั้งที่ได้ของจาก Buy order เดียวกันรวมเป็น **1 lot** และนับ **1 Round-Trip** เมื่อขายหมด ไม่ว่าจะแบ่งขายกี่ครั้ง
  order ที่ได้ของหลายครั้งนับเป็น 1 order ใน `Buy Order Count` / `Sell Order Count`
  - ซื้อ 68,000 (order เดียว) ขาย 30,000 แล้ว 38,000 → 1 Round-Trip
  - ซื้อ 2 order (30,000 + 38,000) ขายหมด → 2 Round-Trip
- รายละเอียดและตัวอย่าง: หัวข้อ "Reading the transaction log" ใน [`api_reference.md`](api_reference.md#reading-the-transaction-log)

### ข้อมูลสำหรับซ้อม
- tick ตั้งแต่ 1 ต.ค. และข้อมูลย้อนหลังล่าสุด อยู่ใน `tradeSim_ticks.zip` / `tradeSim_history.zip` บน Google Drive
  ดูวิธีใช้ใน [`get_historical_data.md`](get_historical_data.md)
